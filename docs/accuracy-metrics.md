# MGPUSim MI300A Accuracy Metrics

## Overview

This document describes the accuracy metrics computed by the CI benchmark workflow
(`benchmark.yml`) when comparing MGPUSim simulation results against MI300A hardware
measurements.

## Primary Error Metrics

The workflow computes two complementary error metrics for every matched
`(hw, sim)` data point where both values are strictly positive:

```
err           = |sim - hw| / hw
symmetric_err = |sim - hw| / min(sim, hw)
```

- **`err`** (hardware-relative error): measures the fractional deviation of the
  simulator from the hardware reference.  A value of 0.10 means the simulator
  is within 10% of the hardware measurement.
- **`symmetric_err`** (symmetric relative error): divides by the smaller of the
  two values, so it is unbounded in both directions and equally penalises
  over- and under-estimation.  It is less sensitive to which direction the
  simulator is biased.

Data points where either value is zero, `NaN`, or absent are excluded from all
metric computations.

## Per-Benchmark Metrics

For each benchmark the report provides:

| Column | Description |
|--------|-------------|
| `mean_err` | Mean of `err` across all matched data points for this benchmark |
| `max_err` | Maximum `err` across matched data points |
| `mean_sym_err` | Mean of `symmetric_err` across matched data points |
| `max_sym_err` | Maximum `symmetric_err` across matched data points |

## Global Metrics

In addition to per-benchmark summaries, the report computes the same four
statistics (`mean_err`, `max_err`, `mean_sym_err`, `max_sym_err`) over all
matched data points across all benchmarks.

## What the Report Contains

The accuracy report (`accuracy_report.md`, generated by
`scripts/generate_comparison_report.py`) includes:

1. **Global summary** — mean and max `err` / `symmetric_err` over all data
   points.
2. **Per-benchmark table** — one row per benchmark with the four metrics above
   and the number of matched data points used.
3. **Per-benchmark charts** — PNG plots (written to `docs/figures/`) comparing
   hardware and simulator execution time as the scaling parameter varies.
   Charts are grouped by non-scaling-parameter combinations when a
   `workloads/<suite>/<bench>/params.json` file is present.

The report is uploaded as a CI artifact named `accuracy-report` and is also
rendered as an HTML page on GitHub Pages (see
[MI300A Benchmark Workflow](../README.md#mi300a-benchmark-workflow)).

## Historical Tier-Based Evaluation

Earlier versions of this document described a three-tier evaluation framework
based on Spearman rank correlation, speedup ratios, and bottleneck-category
coverage.  That framework was used during initial calibration work but
is no longer enforced by CI.  The current CI pass/fail gate is based solely on
the `err` and `symmetric_err` metrics described above.  The tier descriptions
are retained here for reference only.

### Tier 1: Rank-Order Accuracy (reference)

Spearman rank correlation (ρ) between real and simulated execution times across
problem sizes.  A kernel passes if ρ ≥ 0.7; the overall gate required ≥ 80%
of kernels to pass.

### Tier 2: Scaling Accuracy (reference)

Speedup ratio `sim_speedup / real_speedup` computed between the smallest and
largest problem sizes.  A kernel passes if the ratio is in [0.5, 2.0]; the
overall gate required ≥ 55% of applicable kernels to pass.

### Tier 3: Bottleneck Coverage (reference)

Coverage of 12 bottleneck categories (compute-bound, memory-bandwidth,
cache-sensitive, etc.).  The gate required ≥ 8/12 categories to have at least
one benchmark below 100% error.
