# Contributing

## Running the MI300A Benchmark Workflow

To trigger the MI300A benchmark workflow:

1. Navigate to **Actions → benchmark.yml** in the GitHub Actions UI.
2. Click **Run workflow** and select the target branch.
3. The workflow requires self-hosted runners with the following tags: `mi300a`, `self-hosted`.
4. Ensure the runner machine has the MI300A GPU available before dispatching.

## Regenerating the Accuracy Report

The accuracy comparison report is generated by `scripts/generate_comparison_report.py`.

1. Download the simulation output artifacts from the relevant CI run under the **Actions** tab.
2. Place the artifacts in the directory expected by the script (see script docstring for details).
3. Run:
   ```bash
   python3 scripts/generate_comparison_report.py
   ```
4. The report (`accuracy_report.md`) is committed to the repository and updated via CI.

## Interpreting err and symmetric_err Metrics

- **err**: Signed relative error between simulated and reference values. A positive value means the simulator over-reports; negative means under-report. Computed as `(simulated - reference) / reference`.
- **symmetric_err**: Symmetric relative error that treats both directions equally. Computed as `(simulated - reference) / ((simulated + reference) / 2)`. Less sensitive to extreme outliers than plain `err`.

When evaluating accuracy, prefer `symmetric_err` for a balanced view across all benchmarks.

## Workflow Contract

The benchmark workflow enforces the following time and concurrency limits:

| Parameter | Value |
|-----------|-------|
| Workflow order | Validation -> Tier 1 -> Tier-1 summary -> Tier 2 -> Summary |
| Time per simulation | 7200s per simulator invocation (`timeout_sec: 7200`) |
| Time per benchmark-tier job | 360min / 21600s (`timeout-minutes: 360`) |
| Maximum parallel jobs | 14 (`max-parallel: 14`) |

Tier 1 runs before Tier 2. The Tier-1 summary is informational, so Tier 2 may
still run after validation when Tier 1 artifacts are partial or diagnostic.

These limits are configured in `.github/workflows/benchmark.yml` and `docs/runner_configuration.md`.
